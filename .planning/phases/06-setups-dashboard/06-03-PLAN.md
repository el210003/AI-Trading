## Discretion Decisions Pinned In-Plan

- **Performance R basis (A4):** the Performance panel uses the **structural `r_gross`** from each resolved setup (entry vs SL distance), because v1 is signals-only (no cost model). The data layer maps resolved `tp_hit -> WIN`, `sl_hit -> LOSS`, `expired (TIMEOUT) -> TIMEOUT`, and excludes `invalidated`/`pending`/`active` from the stats. It sets both `r_raw` and `r_net` to `r_gross` so it can reuse `stats_by_symbol_timeframe` unchanged, and documents in the panel the live-vs-backtest caveat (the backtest fills at next-open per D-04 while live uses the D-01 limit-trigger, so live is a trigger-filtered subset).
- **Health status semantics (OQ4):** the strip shows **last-persisted state** — `last_bar_time` per (symbol,timeframe) from the bar store and a collector heartbeat from the SQLite `collection_state.last_success_at`; "MT5 disconnected"/stale renders the UI-SPEC copy when the heartbeat is old. No live MT5 probe in the dashboard.
- **Recent errors:** derived from the meta store's recent `bar_gaps` records (data-quality gaps detected in the last N days) surfaced as the health "errors/recent issues" count, reusing existing stores (no new errors table).

|----------|-------------|
| resolved-setup trace -> stats | Setup status/outcome data crosses into the (reused) stats functions; must map honestly |
| bar/meta store -> health | Persisted heartbeat/gap data is rendered as pipeline health |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-06-02 | Tampering | History/health render of stored strings | low | mitigate | Render via Streamlit native widgets only; no `unsafe_allow_html`; statuses/labels from `theme` enums (never raw injected strings) |
| T-06-01 | Tampering | Health/bar data-root paths | medium | mitigate | Paths derive from a fixed config-driven root under a resolve-under-root guard in the data layer |

| T-06-05 | Info Disclosure | Credential/secret leaked into a rendered record | low | mitigate | The dashboard renders only non-secret setup/report/health records; `llm_api_key` stays gitignored and is never read into a view |
