## UI-SPEC Constraints To Honor (do not re-open)

- Palette locked: dominant `#0B0F17`, secondary `#141A26`, accent `#00C7FF`, bull `#26A69A`, bear `#EF5350`, warning `#E0A500`, destructive `#E5484D`; status chips bound exactly per the UI-SPEC color-binding table (active=accent, tp_hit=bull, sl_hit=bear, expired/invalidated=warning; WIN/LOSS/TIMEOUT, agreement agree/disagree/unclear).
- Typography: exactly 4 sizes (16/14/20/28), 2 weights (400/600), `tabular-nums` on all price/probability/R values; probability rendered as a whole percent ("58%").
- Layout: wide single-page, shared left sidebar (global filters) + sticky 56px health strip on every tab + `st.tabs` (Setups/History/Performance/Health). On Setups, the selected-setup candlestick + evidence panel is the SINGLE visual anchor.
- Components: Streamlit native (`st.dataframe`, `st.plotly_chart`, `st.metric`, `st.sidebar`, `st.status`, `st.tabs`), plotly for all charts.
- Refresh model: manual Refresh (`st.rerun()`), NO `@st.cache_data` on the refresh path; only immutable historical artifacts (bars, labels, canonical stats) may be cached with a ttl.
- Honesty: `p_win` always renders beside its `score_source` tag; heuristic in the warning hue; `narrative_status=llm_unavailable` renders `⌀` + reason, never a blank.
- Robustness: a missing/empty store renders the Empty/Error state on the affected view only; other tabs stay functional.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| store (evidence strings) -> Streamlit render | The persisted setup/evidence object is untrusted display data; crossing into the render path |
| data-root path -> filesystem | A dashboard data-root / bar path is derived from config |
| user filter input -> data layer | Sidebar filter values are user input consumed by query logic |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-02 | Tampering | Evidence/detail render in `views_setups` | high | mitigate | Render only via Streamlit native widgets (`st.dataframe`/`st.plotly_chart`/`st.markdown` without `unsafe_allow_html`); never inject raw evidence strings as HTML |
| T-06-01 | Tampering | `data_layer` data-root / bar paths | medium | mitigate | Setup and bar paths derive from a fixed config-driven root under a resolve-under-root guard (mirror `backtest.runner._output_dirs`) |
| T-06-03 | DoS | Missing/empty setup or bars store | medium | mitigate | Defensive reads return schema-correct empty frames; each view renders the Empty/Error state (`st.info`) and suppresses only its own tab |
| T-06-06 | Tampering | Filter input type/range | medium | mitigate | Filter values are typed/bounded in the data layer (min-prob slider 0-100, multiselect over known enum sets) and passed to `apply_filters` as validated values; frozen `Config` validates `setup_*` knobs |
| T-06-05 | Info Disclosure | Credential/secret in the dashboard | low | mitigate | The dashboard reads only non-secret setup/report records (`llm_api_key` stays in gitignored `config.local.toml`); never render the key |
</threat_model>
