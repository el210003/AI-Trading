<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MT5 terminal (IPC) → collector | Terminal responses (rates, ticks, error codes) drive storage; a wrong terminal/account silently poisons data |
| config.local.toml → collector | Local overrides may contain credentials; leakage into logs/errors is the risk |
| collector → stores | Malformed/partial fetch results must never reach storage as "closed bars" |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-SC | Tampering | (carried from 01-01) pinned installs already gated by blocking-human checkpoint | high | mitigate | Pins already locked in pyproject.toml by 01-01; no new installs in this plan |
| T-1-04 | Spoofing | initialize() connecting to the wrong of the two installed MT5 terminals | medium | mitigate | Required explicit cfg.terminal_path (exists-validated); connect_and_verify asserts account_info().server equals cfg.expected_server and fails with both names (Task 2) |
| T-1-05 | Information Disclosure | initialize credentials in logs/exceptions | high | mitigate | Terminal-saved credentials preferred (no login/password config); unit test proves a supplied fake password never appears in any raised message (Task 2) |
| T-1-06 | Tampering (data) | Forming bar persisted as closed (look-ahead contamination of the shared code path) | high | mitigate | copy_rates_from_pos always start_pos=1 (asserted by fake-recording test); merge_and_write forming-bar guard from 01-01 holds on the live write path (Task 4 checkpoint) |
| T-1-07 | Denial of Service (data) | Silent gaps from accepting partial first history responses | medium | mitigate | Retry-until-stable fetch is built in 01-03; this plan's poll cycle only appends bars newer than the checkpoint so partial reads self-heal on the next cycle |
